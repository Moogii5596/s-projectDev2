# ADR-004 — Байгууллагын дотоод Feed: пост, ажлын пост, харагдах эрх, зураг, мэдэгдэл

> Төлөв: **Батлагдсан (шийдвэр) — 2026-10-11** · Хэрэгжүүлэх: v0.3 · Холбоотой: PRD-05, ADR-003 (эрх), v0.2.0 audit log
> Хамрах хүрээнээс гадуур: сурталчилгаа, төлбөр, худалдаа (хассан) · чат (ирээдүйд)

## 1. Шийдвэр

### 1.1 Пост ба ажлын пост
| Төрөл | Хэн | Хэнд харагдана | Ажлын урсгал |
|---|---|---|---|
| **Энгийн пост** (текст, зураг) | Хэн ч (`feed.post`) | Байгууллага / сонгосон кемп | — |
| **Анхааруулга** (ХАБ, удирдлага) | `feed.announce` | Байгууллага / кемп; **дээр тогтоох** (хугацаатай) | — |
| **Хоолны цэс** | Катеринг (`menu.publish`) | Тухайн кемп; өнөөдрийн цэс Feed-ийн дээд хэсэгт | Цэс (v0.2.3-ын хоолны бүтэцтэй нэг) |
| **Засварын хүсэлт** ("Блок 7-00 ус алдаж байна" + зураг) | Хэн ч (`maintenance.create`) | Зохиогч + засвар **гүйцэтгэх/хаах** эрхтэй хүмүүс (тухайн кемп) | Засварын тасалбар автоматаар (OPEN); постын доор **явц**: Нээлттэй → Хийгдэж буй → Дууссан → Хаагдсан |
| **Хоолны гомдол** ("өдрийн хоол давс ихтэй") | Хэн ч (`meal.complain`) | Зохиогч + катеринг + кемпийн менежер | Гомдлын бүртгэл (Шинэ → Хүлээн авсан → Шийдсэн/Тайлбарласан); явц постын доор |
| **Системийн пост** (хог тээвэр, ирц г.м. ажлын бүртгэл) | Систем (event bus) | **Тухайн бүртгэлийн эрхтэй хүмүүс** (жнь `haul.approve`) | Явц постын доор |

- **Харагдах эрх = эрхийн матриц** (ADR-003 `user_permissions`): ажлын пост бүр `visibility` дүрэмтэй (`permission_code` + кемп) → Feed query нь хэрэглэгчийн эрхтэй таарах постуудыг л буцаана (backend-д шүүнэ, frontend-д биш).
- Лайк, сэтгэгдэл — бүх постонд (харах эрхтэй хүмүүс). Ажлын постын сэтгэгдэл = ажлын харилцаа (жнь гүйцэтгэгч "Маргааш засна").
- Засварын хүсэлтийн байршил: өрөө/байр сонгох (хайлттай) **эсвэл** чөлөөт текст ("Блок 7-00") → кемпийн менежер дараа нь өрөөнд холбоно (засварт `location_text` нэмэх, өрөө/хөрөнгө хоосон байж болно — v0.3 migration).

### 1.2 Өгөгдлийн загвар (урьдчилсан)
`feed_posts` (tenant, camp?, author_user_id, type, body, visibility_permission?, linked_entity_type/id, pinned_until?, hidden_at/by/reason, created_at) · `feed_post_media` (storage_path, width, height, bytes) · `feed_reactions` (post, user, type=LIKE; unique) · `feed_comments` (post, author, body, hidden_*) · `feed_post_events` (явц: entity status өөрчлөлт — v0.2.0 audit log/event bus-аас) · `user_notifications` (user, post/comment, kind, read_at) · `feed_posting_restrictions` (user, until, reason, by). Бүгд RLS (tenant).

### 1.3 Унших архитектур
- Байгууллага дотор (хэдэн зуу–мянган хэрэглэгч) → **fan-out хэрэггүй**: `WHERE tenant AND (visibility нээлттэй OR хэрэглэгчийн эрхэд таарна) ORDER BY created_at DESC` + cursor (`idx` tenant, camp, created_at), эрхийн жагсаалтыг Redis-д (≤60с) cache.
- Шинэ пост: 30 сек тутам polling эсвэл Supabase Realtime (пилотод унтраалттай → polling эхэлж).
- Лайк/сэтгэгдлийн тоо — тоолуурын багана (transaction дотор).

### 1.4 Зураг
- Хүлээн авах ≤ 15 MB → сервер дээр шахаж ≤ 5 MB (урт тал ≤ 2048px, JPEG/WebP), **EXIF (GPS байршил г.м.) арилгана**, thumbnail. Пост бүрт ≤ 6 зураг.
- Хадгалалт: пилотод локал диск (`storage/` — нөөцлөлтөд орно, хэмжээг `pilot.ps1 status`-д харуулна) эсвэл Supabase Storage; cloud руу шилжихэд object storage (ADR-002). Хандалт: зөвхөн нэвтэрсэн, постыг харах эрхтэй хэрэглэгч (signed URL / backend proxy).

### 1.5 Зохицуулалт
- Контентод хязгаарлалтгүй (хэрэглэгчийн шийдвэр), гэхдээ:
  - Зохиогч өөрийн постыг засах/устгах.
  - **"Мэдэгдэх"** (report) товч → зохицуулагчид.
  - Зохицуулагч (`feed.moderate`): постыг **нуух** (шалтгаантай) → зохиогчид **мэдэгдэл**; **пост бичих эрхийг хугацаатай хаах** (жнь 7 хоног) → хэрэглэгчид мэдэгдэл; бүгд өөрчлөлтийн түүхэнд.
  - Нуусан пост устахгүй (хуулийн шаардлагаар хадгална), зөвхөн зохицуулагч харна.

### 1.6 Мэдэгдэл
Апп доторх хонх (миний постонд лайк/сэтгэгдэл, ажлын явц, анхааруулга, зохицуулалт). Утсанд апп шиг (PWA). Push мэдэгдэл (Web Push) — v0.3-ын сүүлд эсвэл дараа (хэрэглэгчийн зөвшөөрөлтэй).

## 2. Үр дагавар
- (+) Ажлын урсгал (засвар, гомдол, тээвэр) маягтгүйгээр, ажилтанд танил "пост" хэлбэрээр; явц нэг дор.
- (+) Эрхийн нэг матриц (ADR-003) Feed-ийн харагдах байдлыг ч удирдана.
- (−) Зургийн хадгалалт нэг PC-ийн диск/нөөцийг өсгөнө → хостингийн шийдвэр (ADR-002) v0.3-ын үед хэрэгтэй болно.
- (−) Эрхээр шүүсэн Feed query-ийн гүйцэтгэлийг ачааллын тестээр шалгана (10k пост, 1k хэрэглэгч).
