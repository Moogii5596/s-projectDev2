# ADR-006 — HR модуль: ажилтан системийн суурь болно

> Төлөв: **Батлагдсан (шийдвэр) — 2026-10-13** · Хэрэгжүүлэх: v0.2.2 ([[07_v0.2.2_tech_plan]]) · Холбоотой: [[ADR-003_Users_Login_Permissions]] (хэрэглэгч = ажилтны бүртгэлээс), [[ADR-001_Tenant_Isolation]] (RLS), [[PRD-06_Vision_Business_Model]] (бүх салбар)
> Хэрэгжүүлэлт: **v0.2.2 Блок H1 (backend) + H2 (frontend)** — "одоо зөөж нэрлэх, загварыг v0.3-т" (§5). Checklist → [[07_v0.2.2_tech_plan]] §11.

## 1. Нөхцөл

- Одоо ажилтан, хэлтэс, ээлж, ирц, гэрээт байгууллага бүгд **Кемп модуль дотор** (`camp_*` хүснэгтүүд) байна — пилот Кемпээр эхэлсэн учир.
- Систем зөвхөн уул уурхай / кемпэд биш, **бүх салбарт** (хүргэлт, ресторан, зочид буудал, үйлдвэрлэл…) зориулагдсан ([[PRD-06_Vision_Business_Model]]). Ажилтан бол бүх модулийн суурь.
- [[ADR-003_Users_Login_Permissions]]-аар хэрэглэгчийг **ажилтны бүртгэлээс** үүсгэдэг болсон (v0.2.2 Блок 3) — ажилтан Кемпэд байх тусам хэрэглэгч/эрх ч Кемптэй уягдана.

## 2. Шийдвэр (2026-10-13)

1. **Ажилтан Кемп модулийн хэсэг биш — системийн үндсэн HR модулийн хэсэг.** Кемп модуль ажилтны өгөгдлийг HR-ээс авна.
2. **HR / үндсэн системд:** ажилтан, хэлтэс, ээлж, ирц, гэрээт байгууллагууд.
3. **Кемпэд зөвхөн кемптэй холбоотой:** өрөө, байр, хоолны тоо/захиалга, засвар, хөрөнгө, хог / бохир ус г.м.
4. **Ирц:** одоо байгаагаар нь HR руу **зөөнө**, нэршлийг хүний нөөцийн нэршлээр солино. Ирцийн бүтцийг томоохон ERP-үүдийн (SAP, Odoo г.м.) жишгээр судалж **дараа** засварлана — одоо бүрэн дахин зохиовол үндсэн зорилгоосоо хазайж цаг алдана.
5. Хугацаа: **v0.2.2 дотор**.

## 4. Үр дагавар

- (+) Ажилтан, хэрэглэгч, эрх нэг суурьтай — шинэ модуль (ресторан, хүргэлт…) Кемпээс хамааралгүй ажилтан ашиглана.
- (+) Нэгдсэн feed ([[PRD-06_Vision_Business_Model]]) ажилтны профайлыг HR-ээс авна.
- (+) v0.2.2-т **DB хөндөгдөхгүй** (migration, өгөгдөл шилжүүлэлт алга) — пилотын эрсдэл бараг байхгүй; staging-д `camp:snapshot` A = B ердийнхөөрөө.
- (−) Түр хугацаанд кодын нэр (HR) ба DB / эрхийн нэр (`camp_*`, `camp.*`) зөрнө — v0.3 хүртэл. `@@map` ба энэ ADR-аар баримтжуулна.
- (−) Хуучин `/api/v1/camp/...` замууд нэг хувилбар давхар ажиллана (v0.2.3-т устгана).

## 5. Хэрэгжүүлэлтийн шийдвэр (2026-10-13) — "одоо зөөж нэрлэх, загварыг v0.3-т"

Нээлттэй асуултын хариу: HR-ийг **Блок 4-ийн өмнө** (UI-г нэг удаа HR дээр барина) · биет нэр **хэвээр** (v0.3) · бригад → HR · гэрээ/үнэ, албан тушаалын хоолны тохиргоо → Кемп · олон кемп/салбар → **v0.3**.

### 5.1 v0.2.2 — Блок H1 (backend), H2 (frontend)
- **DB хөндөгдөхгүй:** хүснэгт, өгөгдөл шилжүүлэхгүй; хүснэгтийн нэр (`camp_employees` г.м.) хэвээр.
- **Эрх:** код (`camp.employee.manage` г.м.) хэвээр; **харагдах нэр** HR-ийн нэршлээр (Хүний нөөц › …).
- **Код:** шинэ `modules/hr` — ажилтан, хэлтэс, бригад, албан тушаал, ээлжийн загвар, ээлжийн өөрчлөлт, ирц (ирсэн/явсан, импорт). `modules/core` — байгууллагууд.
- **Prisma:** model-ууд HR нэртэй (`CampEmployee` → `HrEmployee` …), DB нэр `@@map`-аар хэвээр.
- **API:** шинэ `/api/v1/hr/...` (кемп-түвшин `/hr/sites/:campId/...` — `:campId` = үндсэн ажлын байр), `/api/v1/hr/positions`, `/api/v1/core/organizations`. Хуучин `/api/v1/camp/...` замууд **нэг хувилбарын турш** ажиллана (хуучин кэштэй утас эвдрэхгүй) → v0.2.3-т устгана.
- **Цэс:** шинэ «Хүний нөөц» — Ажилтан, Хэлтэс, Бригад, Албан тушаал, Ээлж, Ирц, Импорт. Кемпийн цэсэнд зөвхөн кемпийнх: өрөө, хоол, засвар, хог/бохир ус, хөрөнгө, гэрээ/зардал.
- **Үлдэх хязгаарлалт:** ажилтан нэг кемптэй холбоотой хэвээр — HR дээр **«үндсэн ажлын байр»** гэж харагдана.
- **Ирц ↔ Кемп:** HR нь Кемпийг import хийхгүй — `AttendanceStayStore` порт (`camp_stays`, нэг tx), Кемп `CampHrBridge`-ээр бүртгэнэ; HR экспортод `rooms`-ийг мөн бүртгэнэ.
- **Төлөв:** H1 ✅ (2026-10-14, [[07_v0.2.2_tech_plan]] §11.4).
- **Дараалал:** H1 → H2 → Блок 4 (хэрэглэгч удирдах UI, HR дээр) → Блок 5 (ажлаас гарах, профайл, HR дээр) → Блок 6 (release). Хугацаа: v0.2.2 +1–2 session; v0.2.3–v0.2.4 бараг хэвээр (өгөгдлийн загвар өөрчлөгдөхгүй).

### 5.2 v0.3 — HR-ийн дахин загварчлал
- Ажилтан ↔ кемпийн бүртгэлийг салгах (олон кемп, кемпгүй ажилтан) — «ажлын байр / site» ерөнхий ойлголт.
- HR-ийн хэлтэс ↔ кемпийн хоолны бүлгийг салгах.
- Хүснэгт, эрхийн **биет нэрийг** солих (`hr_*`, `hr.*`) — migration + эрхийн A = B snapshot.
- Ирцийн шинэ давхаргууд (§7): цагийн хуудас, чөлөөний төрөл, үлдэгдэл, батлах урсгал, цалин руу экспорт.

## 6. Томоохон ERP-үүдийн харьцуулалт (товч)

| Давхарга | SAP (HCM / SuccessFactors) | Oracle HCM | Odoo | S Project (v0.2.2 → v0.3) |
|---|---|---|---|---|
| Байгууллагын бүтэц | Company code → Personnel area/subarea → Org unit | Legal entity → Business unit → Department, Location | Company → Department, Work location | Tenant → (Кемп = «үндсэн ажлын байр») → Хэлтэс → v0.3: Site, Хэлтэс тусдаа |
| Ажилтан ↔ ажлын байр | Position (албан тушаалын оронтоо) ↔ Job | Assignment (олон assignment боломжтой) | Employee → Job position | v0.2.2: ажилтан 1 кемп · v0.3: олон assignment |
| Ажлын хуваарь | Work schedule rule | Work schedule / shift | Working schedule (resource calendar) | Ээлжийн загвар (хэлтэс/албан тушаал) + зохицуулалт |
| Ирцийн түүхий өгөгдөл | Time events (clock-in/out) | Time cards / time entries | Attendances (check-in/out) | `camp_movements` (ирсэн/явсан, xlsx импорт) |
| Цагийн хуудас, батлах | Time evaluation → approval | Timecard approval | Timesheets (project) | v0.3 |
| Чөлөө ба үлдэгдэл | Absence types, quotas | Absence plans, accruals | Time Off types, allocations | v0.3 |
| Цалин руу | Payroll integration | Payroll | Payroll (work entries) | v0.3: экспорт (цалингийн модуль биш) |

Дүгнэлт: бүгд **(1) бүтэц, (2) ажилтан-ажлын байр (assignment), (3) хуваарь, (4) түүхий ирц, (5) боловсруулсан цаг / чөлөө, (6) цалин** гэсэн давхаргатай. Манайх одоо (1)–(4)-ийн хялбар хэлбэр — v0.3 нь (2)-ыг салгаж, (5)–(6)-ийг нэмнэ.

## 7. Ирцийн зорилтот бүтэц (v0.3, урьдчилсан)
1. **Түүхий үйл явдал** — ирсэн/явсан (`movements`, импорт, гараар; ирээдүйд төхөөрөмж/апп).
2. **Хуваарь** — ээлжийн загвар + зохицуулалт → өдөр бүрийн төлөвлөсөн хуваарь.
3. **Цагийн хуудас** — (1) + (2) → өдрийн ажилласан цаг, илүү цаг, тасалсан.
4. **Чөлөө** — төрөл (ээлжийн амралт, өвчтэй, цалингүй…), эрх/үлдэгдэл, хүсэлт.
5. **Батлах** — хэлтсийн дарга → HR (workflow модуль ашиглана).
6. **Экспорт** — цалин руу (хугацаа, ажилтан, цагийн төрөл).
> Кемп нь (1)-ээс **байрлалт / хоолны тоо** гаргадаг хэрэглэгч хэвээр (`camp_stays`, presence).
