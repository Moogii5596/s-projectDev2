# ADR-006 — HR модуль: ажилтан системийн суурь болно

> Төлөв: **Батлагдсан (шийдвэр) — 2026-10-13** · Хэрэгжүүлэх: v0.2.2 ([[07_v0.2.2_tech_plan]]) · Холбоотой: [[ADR-003_Users_Login_Permissions]] (хэрэглэгч = ажилтны бүртгэлээс), [[ADR-001_Tenant_Isolation]] (RLS), [[PRD-06_Vision_Business_Model]] (бүх салбар)
> Нарийвчилсан хэрэгжүүлэлтийн төлөвлөгөө (migration, API, UI) — **гаргаж батлуулах** (§5)

## 1. Нөхцөл

- Одоо ажилтан, хэлтэс, ээлж, ирц, гэрээт байгууллага бүгд **Кемп модуль дотор** (`camp_*` хүснэгтүүд) байна — пилот Кемпээр эхэлсэн учир.
- Систем зөвхөн уул уурхай / кемпэд биш, **бүх салбарт** (хүргэлт, ресторан, зочид буудал, үйлдвэрлэл…) зориулагдсан ([[PRD-06_Vision_Business_Model]]). Ажилтан бол бүх модулийн суурь.
- [[ADR-003_Users_Login_Permissions]]-аар хэрэглэгчийг **ажилтны бүртгэлээс** үүсгэдэг болсон (v0.2.2 Блок 3) — ажилтан Кемпэд байх тусам хэрэглэгч/эрх ч Кемптэй уягдана.

## 2. Шийдвэр (2026-10-13)

1. **Ажилтан Кемп модулийн хэсэг биш — системийн үндсэн HR модулийн хэсэг.** Кемп модуль ажилтны өгөгдлийг HR-ээс авна.
2. **HR / үндсэн системд:** ажилтан, хэлтэс, ээлж, ирц, гэрээт байгууллагууд.
3. **Кемпэд зөвхөн кемптэй холбоотой:** өрөө, байр, хоолны тоо/захиалга, засвар, хөрөнгө, хог / бохир ус г.м.
4. **Ирц:** одоо байгаагаар нь HR руу **зөөнө**, нэршлийг хүний нөөцийн нэршлээр солино. Ирцийн бүтцийг томоохон ERP-үүдийн (SAP, Odoo г.м.) жишгээр судалж **дараа** засварлана — одоо бүрэн дахин зохиовол үндсэн зорилгоосоо хазайж цаг алдана.
5. Хугацаа: **v0.2.2 дотор**.

## 3. Одоогийн хүснэгтүүдийн хуваарилалт

| Хүснэгт (одоо) | Шилжих газар | Тайлбар |
|---|---|---|
| `camp_employees` | **HR** | Ажилтан (утас, имэйл, `user_id` — ADR-003) |
| `camp_departments`, `camp_department_shift_patterns` | **HR** | Хэлтэс, хэлтсийн ээлжийн загвар |
| `camp_positions`, `camp_position_shift_patterns` | **HR** | Албан тушаал, ээлж |
| `camp_organizations` | **HR / үндсэн** | Гэрээт байгууллагууд |
| `camp_movements`, `camp_movement_imports`, `camp_shift_adjustments` | **HR (ирц)** | Байгаагаар нь зөөж, нэрийг солино (§2.4) |
| `camp_position_settings` | Кемп (санал) | Албан тушаалын хоолны тохиргоо — кемптэй холбоотой хэсэг |
| `camp_position_role_templates` | Шийдэгдээгүй | Албан тушаал → эрхийн загвар; эрх нь модуль бүрт хамаарна |
| `camp_crews` | Шийдэгдээгүй | Бригад — HR уу, кемп үү |
| `camp_contracts`, `camp_contract_items`, `camp_contract_item_prices` | Кемп (санал) | Үйлчилгээний гэрээ, үнэ — Кемпийн зардлын тайланд |
| `camp_stays`, `camp_room_allocations`, `camp_rooms`, `camp_buildings` … | **Кемп** | Байр, өрөө |
| Хоол, засвар, хөрөнгө, хог/бохир ус (`camp_meal_*`, `camp_maintenance_*`, `camp_asset*`, `camp_haul_records`) | **Кемп** | — |

> "Санал" / "Шийдэгдээгүй" мөрүүдийг хэрэгжүүлэлтийн төлөвлөгөөнд батлуулна.

## 4. Үр дагавар

- (+) Ажилтан, хэрэглэгч, эрх нэг суурьтай — шинэ модуль (ресторан, хүргэлт…) Кемпээс хамааралгүй ажилтан ашиглана.
- (+) Нэгдсэн feed ([[PRD-06_Vision_Business_Model]]) ажилтны профайлыг HR-ээс авна.
- (−) Пилотын өгөгдөл бүхий хүснэгтүүдийг зөөх migration — **өгөгдөл алдагдахгүй**, RLS бодлого хэвээр, staging дээр `camp:snapshot` A = B шалгалт заавал ([[08_v0.2.2_progress]] «Staging дээр заавал шалгах»).
- (−) Кемпийн API / UI / e2e-д ажилтны замууд (`/camp/camps/:campId/employees/...`) өөрчлөгдөнө — Блок 3-ын endpoint-ууд ч хамаарна.
