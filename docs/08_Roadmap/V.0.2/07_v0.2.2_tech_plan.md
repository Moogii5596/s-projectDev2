### 1.1 Нэмэлт шийдвэр — ✅ бүгд батлагдсан (2026-10-12 00:29)

- **Q-A. Username-ийн хэлбэр** — ✅ **ажилтны кодоос**: жижиг үсэг, латин+тоо (`SH1023` → `sh1023`). Кодонд кирилл/зай байвал хасна; давхцвал `-2`. Шалтгаан: код аль хэдийн tenant дотор давтагдашгүй, ажилтан мэддэг. *Өөр сонголт:* овог нэрийн латин галиг (`bat.dorj`) — хятад нэрэнд тохиромжгүй.
- **Q-B. Нэг удаагийн нууц үг** UI-д хэрэгтэй юу? — ✅ **v0.2.2-д үгүй** (линк + имэйл хангалттай; `pilot.ps1 user` нөөц). `must_change_password` механизм ч хэрэгтэй хэвээр (пилотын одоогийн хэрэглэгчид `pilot.ps1`-ээр үүссэн нууц үгтэй → тэднийг хүчээр солиулах эсэх: ✅ **үгүй**).
- **Q-C. Дахин ажилд орсон хүний нэвтрэх эрх** — шинэ ажилтны бүртгэл (Q8) үүсэх нь тодорхой. Нэвтрэх эрх (хэрэглэгч):
  - ✅ **(1) Хуучин хэрэглэгчийг шинэ бүртгэлд шилжүүлнэ** — нэвтрэх нэр (утас) ижил, түүх (хэн юу хийсэн) нэг хүн дээр үлдэнэ; эрх **загвараас дахин** (хуучин шууд эрх цэвэрлэгдэнэ); шилжүүлсэн нь audit-д.
  - (2) Шинэ хэрэглэгч — Supabase-д имэйл давтагдашгүй тул хуучин хэрэглэгчийн дотоод имэйлийг өөрчлөх шаардлагатай, түүх 2 хүн дээр хуваагдана.
- **Q-C2. Ажилтны код дахин ажилд ороход** — ✅ **ижил кодыг зөвшөөрнө**: `uq_camp_employees_code`-ийг "`TERMINATED` биш бүртгэлд давтагдашгүй" partial unique index-ээр солино (§3.6, constraint сулруулах — rollback тайлбартай). *Өөр:* шинэ код заавал (migration огт өөрчлөгдөхгүй, гэхдээ хэрэглэгчид төвөгтэй).
- **Q-D. Q9 хэрэгжүүлэлт** — ✅ Кемп админы загварт `camp.maintenance.parts` + `camp.maintenance.close` нэмнэ (код өөрчлөхгүй; сэлбэг бүртгэх эрх дагалдана). *Өөр:* шинэ `camp.maintenance.start` эрх салгах (flow + тест өөрчлөгдөнө).
- **Q-E. "Ажилтан" загварын эрх** — Feed хараахан байхгүй. ✅ v0.2.2-д: `camp.maintenance.create` (өөрийн засварын хүсэлт) л. Хоолны гомдол/цэс — тэдгээр модуль гарахад нэмнэ.

## 2. Техникийн шийдэл (D-01…D-09)

- **D-01 Эрхийн ганц эх сурвалж** = `camp_user_permissions` (ADR-ийн `user_permissions`). Guard (`camp-access.service.ts` → `resolve()`, ганц цэг) зөвхөн үүнийг уншина. Redis cache (5 мин) + `invalidate(tenantId)` хэвээр.
- **D-02 Загвар = одоогийн `camp_roles` + `camp_role_permissions`** (шинэ загварын хүснэгт үүсгэхгүй). Албан тушаал → загвар: `camp_position_role_templates(position_id, role_id, scope)`. Роль олгох = загварын эрхийг `source=TEMPLATE, template_role_id`-тай **хуулах**. Энэ нь ADR §2.4-ийн `position_permission_templates`-ийг орлоно (ижил утга, одоогийн роль удирдах UI дахин ашиглагдана) → ADR-д "D-02" тэмдэглэл нэмнэ.
- **D-03 Урилга = өөрийн токен** (`core_user_invites`, SHA-256 hash, 72 цаг, нэг удаа). "Линк хуулах" ба "имэйлээр илгээх" нэг токен. Хуудас `/invite/:token` → нууц үг үүсгэх → backend Supabase admin API-аар нууц үг тавина. Шалтгаан: `.invalid` имэйлтэй хэрэглэгчид GoTrue-ийн invite ажиллахгүй, `site_url`-аас хамаарахгүй, audit бүрэн.
- **D-04 Имэйл илгээх** = backend (nodemailer), `.env`: `SMTP_HOST/PORT/USER/PASS/FROM`, `PUBLIC_APP_URL`. 3 хэлний загвар `packages/i18n`-д (хэрэглэгчийн `locale`). "Нууц үг мартсан" ч мөн энэ замаар (жинхэнэ имэйлтэй хэрэглэгчид). Supabase-ийн SMTP тохиргоо **хэрэггүй**.
- ~~**D-05 `resolve-login`**~~ → **D-10-аар орлуулсан** (имэйл задруулах эрсдэл). Анхны санал: **`POST /api/v1/auth/resolve-login {identifier}`** — утас нормчлол (`+976`, зай, зураас хасна → 8 орон), username/имэйл жижиг үсэг. Tenant: идэвхтэй хэрэглэгчдээс нэг л таарвал түүнийх; олон tenant-д таарвал `tenant` талбар шаардана (пилот = 1 tenant). Байхгүй ч **ижил хэлбэрийн** хариу (дотоод имэйлийн хуурамч утга) — задруулахгүй; rate limit (v0.2.1-ийн hook + IP-ээр).
- **D-06 `must_change_password`** — `core_users`-д; `true` бол backend бүх API-г `403 auth.password_change_required` (`@AllowPasswordChangeRequired`: `GET auth/me`, `POST auth/change-password`; гарах нь client-ийн үйлдэл); FE солих хуудас руу. ✅ Блок 2
- **D-10 (✅ Блок 2) Server-ээр нэвтрүүлэх** — `POST /api/v1/auth/sign-in {identifier, password}` (нэвтрэлтгүй): tenant = Host/dedicated (`resolveTenantSlug`, guard-тай нэг дүрэм) → утас/username/имэйлээр **идэвхтэй** хэрэглэгч хайх → GoTrue password grant (хүсэлт бүрт шинэ anon client) → session → FE `supabase.auth.setSession`. Байхгүй/идэвхгүй/буруу нууц үг = ижил 401 (байхгүйд ч GoTrue-г хуурамч `.invalid` хаягаар дуудна); GoTrue түгжээ → 429; GoTrue хүрэхгүй → 503. Имэйл/утас юу ч гадагш гарахгүй. Хязгаар: **зөвхөн амжилтгүй** оролдлого — нэвтрэх нэр 10 / 15 мин, IP (Caddy `X-Real-IP`) 50 / 5 мин; амжилт тоолуурыг тэглэнэ (кемпийн нэг WiFi/NAT).
- **D-11 (✅ Блок 2)** `camp_user_roles.source_position_id` — албан тушаалын загвараас автомат олголт. `camp_employees`-ийн `position_id / user_id / camp_id` өөрчлөгдөхөд **DB trigger** автоматыг л солино (ажилтан засах, бөөнөөр, Excel импорт, холбох API — бүгд). Гараар олгосон ижил роль × кемп байвал хэвээр (`ON CONFLICT DO NOTHING`). Загвар өөрчилсний дараа: `POST positions/:id/role-templates/apply`.
- **D-12 (✅)** Нууц үг ≥ 12 (Supabase `minimum_password_length`; ADR-ийн 10-ыг орлоно).
- **D-13 (✅)** Холбоход: Монгол 8 оронтой, идэвхтэй хэрэглэгчдийн дунд давтагдашгүй утас → `core_users.phone`; үгүй (утасгүй / гадаад / давхардсан) → ажилтны кодоос `username`. Имэйлээр нэвтрэх хүн бүрт хэвээр.
- **D-07 Ажлаас гарах** (нэг `$transaction`): ажилтан `TERMINATED` + огноо/шалтгаан → өрөөний хуваарилалтыг огноогоор хаах → хэрэглэгч `is_active=false` → Redis cache цэвэрлэх → Supabase session хүчингүй (admin `signOut`/ban). Audit мөр.
- **D-08 PIL-03** — `camp_pii_access_log` (тусдаа хүснэгт, audit log-ийг дүүргэхгүй): профайл нээсэн хэн/хэзээ/аль ажилтан. Харах эрх: Кемп админ + tenant admin.
- **D-09 (✅ 2026-10-12, Блок 1)** `camp_user_roles` = **загвар олгосон бүртгэл** (устгахгүй — §3.1-ийн "v0.3-д устгана"-г орлоно). `camp_user_permissions`-ийн `TEMPLATE` мөр бүр `user_role_id`-аар олголтдоо холбогдоно (олголт устахад CASCADE); олголт нэмэгдэхэд **DB trigger** загварыг хуулна → `pilot.ps1 user` (raw SQL), тестийн туслах, RBAC service өөрчлөлтгүй зөв. Загвар өөрчлөгдөхөд хэрэглэгч рүү автоматаар тархахгүй: `GET roles/:id/apply-preview` → `POST roles/:id/apply`. Нэг эрх олон эх сурвалжаас (2 роль / роль + шууд) → мөр бүр нэг эх сурвалж, guard DISTINCT.

## 5. Тест

### 5.1 Эрхийн snapshot — **заавал (A = B)**
`perm-snapshot.ts` → `(tenant, user, permission, camp|*)`-ийн эрэмбэлсэн жагсаалт + мөрийн тоо + SHA-256:
- **A** = хуучин зам (`camp_user_roles ⋈ camp_role_permissions`, DISTINCT) + tenant admin тэмдэг
- **B** = шинэ зам (`camp_user_permissions`)
- Тест: integration (cloud) — A = B; **staging** (пилотын нөөц дээр): A = B
- Нэмэлт: guard түвшинд — хэрэглэгч бүр × эрх бүр × кемп бүрт `can()` өмнө/дараа ижил (staging-д скриптээр)

### 5.2 Q9-ийн хүлээгдэж буй зөрүү
Upgrade-ийн **өмнөх** snapshot (хуучин зам) ба **дараах** (шинэ зам)-ын зөрүү = яг "Кемп админ рольтой хэрэглэгч × {`parts`, `close`}" (давхардсаныг хасаад). Өөр нэг ч мөр нэмэгдэх/хасагдах ёсгүй → үгүй бол **зогсоно**.

### 5.3 Бусад
- Unit: утас нормчлол, username үүсгэгч, identifier ялгах, токен хугацаа/нэг удаа
- Integration: `resolve-login` задруулахгүй (байгаа/байхгүй ижил хариу), `PASSWORD_CHANGE_REQUIRED`, идэвхгүй/ажлаас гарсан хэрэглэгч нэвтрэхгүй + cache, RLS (өөр tenant-ийн хэрэглэгч/урилга/PII лог), ажлаас гарах transaction (өрөө чөлөөлөгдсөн), дахин ажилд авах
- e2e: утас / username / имэйлээр нэвтрэх; урилгын линкээр нууц үг үүсгэх; хуучин имэйл нэвтрэлт
- Бүтэн suite — блокийн төгсгөлд **нэг удаа** (PROC-015)

### 10.2 Олдвор — CNAME дангаараа ажиллахгүй
Tailscale Funnel нь **зөвхөн `*.ts.net`** нэрэнд TLS сертификат олгож, SNI-ээр чиглүүлдэг. `https://sino.gobiverse.website` → хөтөч TLS алдаа (`SSL_ERROR_SYSCALL`) авна. Албан ёсны дэмжлэг алга (tailscale/tailscale #11563 нээлттэй, #16478). DNS зөв — асуудал нь TLS/SNI.

### 10.3 Шийдвэр (Q-G = **B**, 2026-10-12) → **ADR-005**
- Хувилбарууд: A Oracle VM proxy (зөвлөмж байсан) · **B Cloudflare Tunnel** · C түр redirect. Oracle Always Free — **"Out of Capacity"** → **B** сонгосон. Oracle VM — v0.2.4 PIL-06 хостингийн шийдвэрт дахин.
- `gobiverse.website` дээр **олон байгууллага** → ADR-005: байгууллага бүр `<байгууллага>.gobiverse.website`, байрлалаасаа хамаарч 5 төрөл (дотоод сүлжээ / тэдний VM / манай нийтийн сервер / air-gapped / өөрийн домэйн); нэрлэх дүрэм `<байгууллага>-<орчин>` (2 түвшин хориотой — Universal SSL); `.gobiverse.website` cookie хориотой.
- Sino: дэд домэйн `sino` хэвээр (slug `sinohydro`; dedicated тул домэйноос үл хамаарна).
- ⚠️ TLS Cloudflare дээр тайлагдана — пилотын өгөгдөл Cloudflare-аар дамжина (ADR-005 §3).

```
Хэрэглэгч ─https://sino.gobiverse.website─► Cloudflare (TLS) ─tunnel─► cloudflared (таны PC) ─► Caddy 127.0.0.1:8088 ─► апп
```
