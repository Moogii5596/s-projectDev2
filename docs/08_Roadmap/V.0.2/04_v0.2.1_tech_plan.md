## 1. Хэрэглэгчийн шийдвэр (Q1–Q5)

| # | Хариулт | Утга (кодонд) |
|---|---|---|
| Q1 | Хэлтсээс хоолны байршил тохируулахыг **бүр мөсөн болино**. Зөвхөн **албан тушаал (анхдагч) → ажилтан (эцсийн)** — эрх тохируулдагтай адил | Ажлын хоолны байршил = `ажилтан.хоолны_байршил ?? албан_тушаал(кемп).хоолны_байршил ?? кемпийн анхдагч байршил`. Хэлтэс = зөвхөн зохион байгуулалт (тайлан, шүүлт) |
| Q2 | Албан тушаал = **байгууллагын нийтийн каталог** | `camp_positions` (tenant түвшин). Хоолны байршил кемп бүрт өөр тул анхдагч утгыг **кемп × албан тушаал**-аар (§2.2) |
| Q3 | Хоолгүй = хоолны зардал даадаггүй (байрны зардал даадаг байж болно). **Өрөөний самбар, ирцэд хамаарагдана** (хаана, хэд хоносон чухал) | Ажилтан дээр `хоол_авах` (тийм/үгүй), албан тушаалаас анхдагч. Үгүй бол хоолны тоонд **огт** орохгүй (ирэх/явах өдөр ч), харин ирц, хоног, өрөө хэвээр. Хоол/байрны зардал хэн даах → V2-04 (v0.2.4) |
| Q4 | Байрны төрлийг **админ үүсгэнэ** | `camp_building_types` (байгууллагын каталог, Системийн тохиргоо) |
| Q5 | (Надад даатгав) | "Ээлжээр шүүх" = **тухайн өдрийн тооцоолсон ээлж** (Өдөр / Шөнө / Тодорхойгүй / Ирэх-явах өдөр) — хоолны тооцоотой ижил логик (`employeeDay`) |

### Батлуулах нэмэлт шийдвэр (санал)

| # | Асуулт | Санал |
|---|---|---|
| **Д-1** | Ээлжийн загвар (өдөр/шөнө, 1–14 өдөр) одоо хэлтэс дээр. FB-01: "өдөр/шөнийг хэлтсийн оронд албан тушаалаар" | Хоолны байршилтай адил: **кемп × албан тушаал** дээр загвар; албан тушаалд загваргүй бол **хэлтсийн одоогийн загвар** (шилжилтийн хугацаанд, одоогийн өгөгдөл өөрчлөгдөхгүй). Хэлтсийн загварыг v0.2.2-т "хуучирсан" гэж тэмдэглэнэ |
| **Д-2** | "Хоол авах эсэх" хаана тохируулах | **Ажилтан (эцсийн) ← албан тушаал (анхдагч)** — Q1-тэй ижил загвар. Хэлтсээр олноор нь тохируулах: ажилтны жагсаалтаас олныг сонгож "Хоолгүй болгох" + Excel импорт |
| **Д-3** | Одоогийн өгөгдлийг шилжүүлэх | Ажилтан бүрт хэлтсийнх нь хоолны байршлыг **ажилтан дээр хуулна**, `хоол_авах = тийм` → хоолны тоо **яг хэвээр** (staging A = B). Албан тушаалын чөлөөт текстээс каталог үүсгэнэ (давхардлыг жижиг/том үсэг, зайгаар нэгтгэнэ) |
| **Д-4** | `camp_departments.meal_location_id` | v0.2.1-д заавал биш болгож уншихаа болино; багана нэг хувилбар хадгалагдаж v0.2.2-т устгана (буцаах боломж) |

## 2. Өгөгдлийн загвар (migration — бүгд нэмэлт, хуучныг устгахгүй)

> Бодит файлын нэр (#15-д зассан): `20261012001…005`. 2.2-ын файл `20261012002_camp_position_settings.sql`. #15-д нэмэгдсэн: `20261012006_auth_password_guard.sql` (PIL-07, SEC-007).

### 2.1 `20261012001_camp_positions.sql`
- `camp_positions` (tenant_id, id, code, name, is_active, timestamps) — UNIQUE (tenant, code), (tenant, lower(name)); RLS (PERMISSIVE app_user, FORCE, GRANT — `camp_apply_tenant_rls`)

### 2.2 `20261012002_camp_position_settings.sql`
- `camp_position_defaults` (tenant_id, camp_id, position_id, meal_location_id NULL, meals_included BOOL NULL) — PK (tenant, camp, position); FK кемпийн байршил (ижил кемп)
- `camp_position_shift_patterns` (tenant_id, camp_id, position_id, day_from, day_to, shift) — хэлтсийн загвартай ижил бүтэц, EXCLUDE давхцал

### 2.3 `20261012003_camp_employees_position_meals.sql`
- `camp_employees`: `position_id` (NULL, FK каталог), `meal_location_id` (NULL, FK ижил кемп), `meals_included` BOOL NULL (NULL = албан тушаалаас/анхдагч тийм)
- Backfill (нэг transaction): чөлөөт `position` текстээс каталог → `position_id`; `meal_location_id = department.meal_location_id`
- `position` (текст) багана хадгалагдана (v0.2.2-т устгана)

### 2.4 `20261012004_camp_departments_meal_location_optional.sql`
- `camp_departments.meal_location_id` → NULL зөвшөөрнө (Д-4)

### 2.5 `20261012005_camp_building_types_asset_building.sql`
- `camp_building_types` (tenant, id, name, is_active) + `camp_buildings.type_id` (NULL)
- `camp_assets.building_id` (NULL) — өрөөнд биш, байранд байрлах хөрөнгө (агуулахын оронд); CHECK: room_id ба building_id хоёулаа NULL биш бол өрөө тухайн байрных (trigger)
