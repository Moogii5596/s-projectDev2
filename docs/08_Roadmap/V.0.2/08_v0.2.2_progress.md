## Staging дээр заавал шалгах (v0.2.1 → v0.2.2)
- **Блок 6б (SEC-009) — эхэнд:** хэрэглэгч, роль удирддаг хүн(үүд) OWNER / ADMIN эсэх (`pnpm camp:snapshot` → `campAdmins` ба core role). Үгүй бол `pilot.ps1 user`-ээр ADMIN болгоно — v0.2.2-оос Кемп админ хэрэглэгч / роль удирдахгүй. TC-v022-19…22.
- Upgrade-ийн **өмнө** A: `pnpm camp:snapshot --env=<staging .env> --out=a.json` (v0.2.2-ын кодоор — v0.2.1 schema дээр ч ажиллана)
- Upgrade-ийн **дараа** B: `pnpm camp:snapshot --env=<staging .env> --out=b.json --like=a.json`
- `pnpm camp:snapshot --compare a.json b.json --expect=v022-q9` → **✅ A = B** байх ёстой (зөвхөн Кемп админ × засвар эхлүүлэх/хаах + ажлаас гаргах (`camp.employee.terminate`, Блок 5) нэмэгдэнэ). Өөр мөр гарвал **зогсоно**
- **Блок 5:** туршилтын ажилтан (нэвтрэх эрхтэй, кемпэд байгаа, өрөөтэй) → профайл → «Ажлаас гаргах» → тэр хүн нэвтэрч чадахгүй (GoTrue ban), «Ирц»-д явалт, өрөөний самбар чөлөөтэй, хоолны тоонд ороогүй; «Дахин ажилд авах» → ижил утсаар нэвтэрнэ, эрх = албан тушаалын загвар; «Хэн үзсэн» мөр
- "Роль ба эрх" дээр "Ажилтан" багана харагдана; нэг ролийн эрхийг өөрчилж хадгалахад "хэрэгжүүлэх" цонх гарна
- **Блок 3:** (1) Ажилтны картаас имэйлгүй хэрэглэгч үүсгэх (`POST …/employees/:id/create-user`) — GoTrue `u-…@<slug>.login.invalid` хаягийг хүлээж авна уу (**хамгийн чухал**; татгалзвал 400 `auth.user_invalid` + шалтгаан); (2) "Линк хуулах" → утаснаас `/invite/…` → нууц үг → утсаар нэвтрэх; (3) `.env` `SMTP_*` бөглөөд имэйл урилга + "Нууц үг мартсан" ирэх эсэх (spam хавтас); (4) ижил линкийг дахин нээх → "аль хэдийн ашигласан"
- **Блок 2:** `pnpm camp:login-report --env=<staging .env>` (зөвхөн тоо) → утсаар / username-аар хэдэн хүн нэвтрэхийг харна
- Caddy дахин асаасны дараа: имэйлээр нэвтрэх (хуучин) ✅; туршилтын ажилтныг хэрэглэгчтэй холбоод (`PUT …/employees/:id/user`) утсаар ✅, хятад ажилтныг username-аар ✅; буруу нууц үг → "Нэвтрэх нэр эсвэл нууц үг буруу"; `pilot.ps1 auth-test` (түгжээ) хэвээр 429
