## 23. Баримт бичиг — Obsidian vault (2026-10-13)

### [DOC-002] Файлын нэрээр (basename) линк хөрвүүлэхэд vault-ийн гадна файл андуурч холбогдох
- **Алдаа:** `` `README.md` `` (repo root-ийн README, vault-ийн гадна) лавлагааг script `[[README]]` болгож, vault доторх өөр `08_Roadmap/_design_mockups/README.md` руу буруу холбосон (2 газар). Мөн `Root lessons_learned.md` (root заагч файл) → `[[lessons_learned]]` (docs файл) болж утга нь өөрчлөгдсөн.
- **Шалтгаан:** Хөрвүүлэлт зөвхөн файлын нэрийг тулгасан; лавлагааны замыг (root / `apps/…` / vault дотор) шалгаагүй. `_learning/` нүүсний дараа `README` нэр давхардсан.
- **Шийдэл:** Буцааж `` `README.md` `` болгосон. Шалгах script-д (1) замын тулгалт (лавлагааны зам ↔ олдсон файлын зам), (2) давхардсан нэрийн жагсаалт, (3) dangling / orphan шалгалт нэмсэн.
- **Дүрэм:** Vault-д нэр давхардвал `[[хавтас/нэр|харагдах нэр]]` замтай линк ашиглана. Vault-ийн гадна файл (repo root, `apps/`, `supabase/`) → backtick-ээр үлдэнэ, хэзээ ч `[[...]]` болгохгүй. Бөөнөөр хөрвүүлэхийн өмнө `docs/`-ийг нөөцлөөд dry-run тайлан гаргана.

### [DOC-003] Нэг мэдээлэл олон газар → баримтууд хоорондоо зөрөх
**Тохиолдсон (2026-10-13, бүрэн шинжилгээ):** хувилбарын хүснэгт 4 газар (INDEX, project-status, Roadmap, VERSIONING), архитектурын хэв маяг 3 газар; backlog (C-10/C-13 = v0.2.2) ↔ бүтэн төлөвлөгөө (v0.2.3) зөрсөн; lessons-ийн гар индекс 135-аас 100 ID-тэй; 2026-09-ийн "Approved" spec-үүд (`SET LOCAL`, PgBouncer, Express, Kubernetes) одоогийн кодтой зөрчилдөж байсан; project-status-д ашиглагдаагүй Zustand.
**Шалтгаан:** мэдээлэл бүрийн "эзэн" файл тодорхойгүй; индекс гараар хөтлөгдсөн; хуучин spec-ийн статусыг хэн ч шинэчлээгүй.
**Дүрэм:** мэдээллийн төрөл бүр **ганц эх сурвалжтай** ([[CONTEXT]] §5) — бусад газар зөвхөн линк. Кодоос / дэлгэрэнгүйгээс гаргаж болох индекс бүр автомат (`pnpm docs:gen`). Хэрэгжилтээс хоцорсон spec → бүрэн шинэчлэх эсвэл `Archived` + одоогийн баримт руу заагч; "Approved" гэдэг нь "одоо үнэн" гэсэн үг биш.

### [PROC-017] Хэрэглэгчийн машин руу багцаар бичихэд `tar` хуучин файлыг устгах гэж унав
**Тохиолдсон (2026-10-13):** баримтын шинэчлэлийг `tar xzf`-ээр задлахад байгаа 31 файл дээр `Cannot open: File exists` — tar дарж бичихээс өмнө файлыг unlink хийдэг, холбогдсон хавтсанд устгах эрх (default) алга. Шинэ файлууд, `mv` амжилттай.
**Дүрэм:** байгаа файлыг дарж бичихдээ түр хавтсанд задлаад `cp -f` (агуулгыг шууд дарна, устгахгүй); бичихээс өмнө `md5sum -c` (хэрэглэгч хооронд нь өөрчилсөн эсэх), дараа нь `md5sum -c` (бүгд бичигдсэн эсэх). Commit хийсэн файлын md5-ийг шалгалгүй "бичигдсэн" гэж үзэхгүй (stage-ийн хуучин хувилбар бичигдсэн тохиолдол гарсан).
