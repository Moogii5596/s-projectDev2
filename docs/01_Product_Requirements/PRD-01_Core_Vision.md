# PRD-01 — Бүтээгдэхүүний тойм ба үндсэн ойлголтууд

> Хувилбар 2.0 (2026-10-13, бүрэн шинэчилсэн). Алсын хараа, бизнес загвар: [[PRD-06_Vision_Business_Model]] · архитектур: [[ARCH-00_System_Overview]] · анхны хувилбар (2026-09, microkernel/manifest): [[PRD-01_Core_Vision.v1]] — архив.

## 1. S Project гэж юу вэ
S Project бол хүмүүсийн харилцаа, санаа, асуудлыг шаардлагатай үед хамтын шийдвэр, ERP ажлын урсгал, бодит үр дүнтэй холбодог олон байгууллагын (multi-tenant) платформ. Хэрэглэгчид ойлгомжтой, сошиал мэт орчинд өөрсдөө оролцоно; ERP нь арын ажлыг гүйцэтгэнэ. Гол ялгарах чиглэл нь **яриа → хамтын шийдвэр → ажил → үр дүн** юм (✅ хэрэглэгч баталсан 2026-11-07; өмнөх томъёолол «гаднаа нийгмийн сүлжээ, цаанаа ERP» — 2026-10-11 — үүний суурь хэвээр). Бүх салбарт (уул уурхай/кемп, хүргэлт, ресторан, зочид буудал, үйлдвэрлэл, худалдаа…) зориулагдсан; эхний салбар нь **уурхайн кемпийн катеринг** (пилот: Sino Hydro, 2026-10-10-аас).

> Чиглэл батлагдсан; хэрэгжүүлэх UX, шаардлага, хувилбарын дараалал нь тусдаа шийдвэрлэгдэнэ ([[PRD-05_Internal_Social_Feed]] §6) — доорх модулийн хүрээ, батлагдсан хувилбарын дарааллыг өөрчлөхгүй. Feed v0 нь v0.2.3 Блок 5-д хэрэгжсэн суурь хэвээр ([[project-status]]).

## 2. Хэрэглэгчид (актор)

| Актор | Хэн | Одоо юу хийдэг |
|---|---|---|
| Платформын админ | S Project баг | Tenant үүсгэх (onboarding, super admin), deploy, хувилбар шинэчлэх |
| Байгууллагын эзэн / админ (OWNER, ADMIN) | Байгууллагын IT / удирдлага | Бүх кемпийн бүх эрх, тохиргоо, хэрэглэгч, орчуулгын засвар |
| Кемп админ / менежер / катеринг админ | Кемпийн ажилтнууд | Мастер өгөгдөл, ирц, өрөө, хөрөнгө, засвар, хоолны тоо (Кемп RBAC) |
| Ажилтан (EMPLOYEE) | Бүх ажилчид | Нэвтрэх (утас/username), засварын хүсэлт; цаашид feed, хүсэлтүүд |
| Хүсэгч / батлагч (REQUESTER, APPROVER) | Худалдан авалтын урсгал | Шаардах хуудас (MR) үүсгэх, батлах |

## 3. Үндсэн ойлголтууд
- **Tenant (байгууллага)** — өгөгдлийн тусгаарлалтын нэгж (`tenants`, бүх хүснэгтэд `tenant_id` + RLS). Дэд домэйн `<байгууллага>.gobiverse.website`.
- **Байршуулалт** — shared (олон tenant нэг DB) эсвэл dedicated (нэг байгууллага, тусдаа deploy) → [[PRD-02_Tenant_Tiers]].
- **Хэрэглэгч ↔ ажилтан** — хэрэглэгчийг **ажилтны бүртгэлээс** үүсгэнэ (урилгын линк/имэйл); нэвтрэх нэр = утас (8 орон), эс бөгөөс username / имэйл ([[ADR-003_Users_Login_Permissions]]).
- **Ажилтан (HR суурь)** — ажилтан, хэлтэс, ээлж, ирц, гэрээт байгууллага нь системийн суурь HR-д; салбарын модулиуд (Кемп г.м.) HR-ээс уншина ([[ADR-006_HR_Core_Module]], v0.2.2).
- **Эрх** — core role (OWNER/ADMIN/APPROVER/REQUESTER/VIEWER) + модулийн эрхийн код (`camp.*`); албан тушаал = эрхийн загвар, эцсийн эрх хэрэглэгч дээр ([[05_Permissions_Catalog]]).
- **Модуль** — нэг бизнесийн хүрээ (Кемп, MR, Budget…). Модуль бүр асааж/унтраах боломжтой (одоо build-ийн `VITE_MODULES`); бүтэн "суулгах/түдгэлзүүлэх" lifecycle — 🧭 ([[ARCH-00_System_Overview]] §3).

## 5. Бүтээгдэхүүний зарчим
1. **Ажилтанд ойлгомжтой** — утсаар (390px) бүрэн ажиллана, монгол хэл анхдагч, хятад/англи бүрэн ([[PRD-04_UI_UX_Architecture_Spec]]).
2. **Өгөгдөл хатуу тусгаарлагдсан** — байгууллага хооронд, мөн сошиал ↔ ERP хооронд ([[ADR-001_Tenant_Isolation]]).
3. **Бодит ажилд тулгуурласан** — пилотын санал (`FB-*`, `PIL-*`) нь backlog-ийн гол эх сурвалж ([[pilot-feedback]], [[00_backlog_and_tech_debt]]).
4. **Ярианаас үр дүн рүү** — харилцааг ажил болгох нь хэрэглэгчид утгатай үед л; энгийн постыг заавал тасалбар болгохгүй. Ажил болсон бол эх яриа, хариуцагч, явц, үр дүнгийн холбоог ойлгомжтой хадгална.
5. **Аюулгүй шинэчлэл** — хувилбар бүр staging-д, өгөгдлийн snapshot A = B шалгалттай ([[04_Pilot_Camp_Windows]]).
6. **Энгийн архитектур** — шаардлагагүй бол микросервис, тусдаа DB үүсгэхгүй ([[ARCH-00_System_Overview]] §5).
