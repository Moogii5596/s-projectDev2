 PRD-01: Core Vision & Architecture Philosophy
Document ID: PRD-01
Project: S Project
Status: Approved
Version: 1.1.0
Owner: Lead IT Product Manager

1. Executive Summary & Product Vision
S Project нь орчин үеийн үйлдлийн систем (OS Kernel)-тэй ижил концепцоор ажиллах Microkernel Architecture бүхий Hybrid SaaS Multi-Tenant платформ юм.
Платформын гол философи нь суурь цөм системд аливаа өөрчлөлт оруулахгүйгээр бизнесийн төрөл бүрийн модулиудыг дур дураараа залгах (Plug-in), салгах (Unplug), түдгэлзүүлэх (Suspend) боломжийг бүрдүүлэхэд оршино.

2. Архитектурын Философи: Zero Business Logic Core
Цөм систем (Core Kernel) нь дараах хатуу зарчмуудыг баримтална:
Zero Business Logic:
Core Kernel нь ямар нэгэн бизнесийн тусгайлсан логик (жишээ нь: агуулахын хөдөлгөөн, бараа захиалах, цалин бодох, амралт хүсэх)-ийг агуулахгүй.
Бүх бизнесийн үйл ажиллагаа бие даасан модулиудад хадгалагдана.
Core Kernel-ийн үндсэн үүрэг:
Authentication & Identity Management: Нэгдсэн нэвтрэлт, хэрэглэгчийн бүртгэл, баталгаажуулалт (JWT / Session).
Tenant Routing & Ingress Resolution: Ирж буй сүлжээний хүсэлтийг (Tenant-ID, subdomain эсвэл custom domain-аар) тохирох байгууллага, тохирох модулийн сервис рүү чиглүүлэх (Reverse Proxy).
Unified Access Control (RBAC / ABAC ACL): Хэрэглэгчийн үүрэг, хандалтын эрхийг платформ болон модуль түвшинд нэгдсэн хяналтаар хангах.
Module Registry & Lifecycle Orchestrator: Модулиудын холболт, хувилбар, хамаарал (dependency tree), амьдралын мөчлөгийг удирдах.
Event Bus & Notification Infrastructure: Модулиудын хооронд өгөгдөл солилцох Pub/Sub брокер болон системийн мэдэгдлийн суваг.
Central Audit Trail: Системийн төлөвийн бүх өөрчлөлтийг баталгаажуулан хадгалах лог дэд бүтэц.

3. Модульчлалын Зарчим & Shared System Modules
Бизнесийн тусгайлсан модуль тус бүр өөрийн гэсэн approval логик хөгжүүлбэл кодын давхардал үүсэх, харин Core дотор шийдвэл Core монолит болох эрсдэлтэй. Иймээс дараах архитектурыг мөрдөнө:
Business Modules (Жишээ: Material Requisition, Inventory, HRMS):
Зөвхөн өөрийн бизнесийн анхан шатны өгөгдөл, CRUD дүрмийг хариуцна.
Shared Cross-Cutting System Modules (Жишээ: workflow-engine, notification-engine):
Core-ийн код биш боловч платформын бусад модулиудад баталгаажуулалтын шатлал, дүрэм матриц, бодит цагийн мэдээлэл хүргэх үйлчилгээ үзүүлдэг дундын модулиуд байна.
Бүх харилцааг Core Event Bus болон дотоод стандартын API-аар дамжуулан зохион байгуулна.

4. Module Lifecycle (Модулийн Амьдралын Мөчлөг)
Модуль бүр өөрийгөө Core-д танилцуулах manifest.json агуулах бөгөөд амьдралын мөчлөг нь дараах 4 үе шат болон "Draining" завсрын горимоор удирдагдана.
4.1 Төлөвийн Шилжилтийн Диаграмм
[Uninstalled] ──(Install)──> [Installed / Inactive] ──(Activate)──> [Active]
                                    ▲                                   │
                                    │                               (Suspend)
                               (Re-activate)                            │
                                    │                                   ▼
                                    │                           [Draining Mode]
                                    │                                   │ (Grace Period)
                                    │                                   ▼
                                    └────────────────────────────── [Suspended]
                                                                        │
[Uninstalled] <────────────────(Uninstall)──────────────────────────────┘
4.2 Амьдралын Мөчлөгийн Бизнес Дүрэм
Install (Суулгах):
Модулийн схем (хүснэгт, DocType), анхдагч тохиргоог Tenant-ийн орчинд бэлтгэж, Core Registry-д бүртгэнэ.
Шалгуур: Тухайн Tenant-ийн багцын модулийн тооны хязгаар (Tier quota) болон урьдчилсан хамааралтай модулиуд (dependencies) бүрэн суулгагдсан эсэхийг Core шалгана.
Үр дүн: Төлөв Installed (Inactive) болно. UI болон API чиглүүлэлт нээгдэхгүй.
Activate (Идэвхжүүлэх):
Модулийн үндсэн тохиргоо болон эрхийн тохиргоо (RBAC mapping) хийгдсэний дараа хэрэглэгчдэд нээлттэй болгоно.
Үр дүн: Төлөв Active болно. Reverse Proxy замууд идэвхжиж, UI цэс болон виджетүүд ил харагдан, Event Bus дээрх эвентүүдийг сонсож эхэлнэ.
Suspend & Graceful Draining (Түр зогсоох):
Системийн засвар үйлчилгээ, төлбөрийн асуудал эсвэл шинэчлэлтийн үед шууд хаахгүй, "Graceful Drain" зарчмыг хэрэгжүүлнэ.
Draining Горим:
Шинээр баримт үүсгэх (CREATE) хүсэлтийг шууд 503 Service Maintenance (Draining) алдаагаар блоклоно.
Тухайн агшинд нээлттэй байсан гүйлгээ, батлах урсгал (in-flight transaction, approvals)-уудыг гүйцээж дуусгах 5-15 минутын "Grace Period" хугацаа олгоно.
Даалгаврын дараалал бүрэн дууссаны дараа модуль автоматаар Suspended төлөвт шилжинэ.
Suspended Төлөв: Модулийн бичих эрхүүд хаагдаж, бүх хэрэглэгчид зөвхөн Read-Only горимд ажиллана. Түүхэн өгөгдөл бүрэн хадгалагдана.
Uninstall (Устгах / Салгах):
Зөвхөн Suspended эсвэл Inactive төлөвт байгаа, өөр бусад идэвхтэй модулиуд хамаараагүй тохиолдолд зөвшөөрөгдөнө.
Өгөгдөл хадгалалтын бодлого (Retention):
Soft Uninstall (Өгөгдмөл): Модулийн холболтыг салгаж, өгөгдлийг архивлан 90 хоног хадгална.
Hard Purge: Байгууллагын эзэмшигчийн 2FA баталгаажуулалтаар бүх өгөгдлийг баазаас цэвэрлэнэ (Core Audit Log түүх хэвээр үлдэнэ).
