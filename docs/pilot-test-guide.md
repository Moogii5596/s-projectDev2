# Кемп пилот — Бодит өгөгдөл оруулах ба туршилтын заавар (v0.1.6.1 … v0.2.3)

> Байгууллага: **Sino Hydro** · Хаяг: **https://sino.gobiverse.website** (2026-10-13-аас; хуучин `…ts.net` Funnel хаяг хаагдсан) · Үүсгэсэн: 2026-10-11
> Админ (систем) талын заавар: [[04_Pilot_Camp_Windows]] · Санал бүртгэх: [[pilot-feedback]]
> **Пилот дууссан гэх шалгуур:** §7-ийн бүх мөр ✅ (шийдвэр D3, [[01_plan_draft]])

Энэ заавар нь бодит өгөгдлийг ямар дарааллаар оруулах, юуг хэрхэн шалгах, асуудлыг хэрхэн бүртгэхийг тодорхойлно.
Систем **хувийн мэдээлэлтэй** (ажилтны нэр, утас, байршил) — §6-ийн дүрмийг бүх хэрэглэгчид мэдэгдэнэ.

---

## 1. Бэлтгэл — хэрэглэгч ба эрх

Хэрэглэгчийг зөвхөн систем хариуцагч (пилот компьютер дээр) үүсгэнэ:
```powershell
cd E:\MoogiiDev\Pilot\s-project
.\deploy\pilot\pilot.ps1 user --email=<email> --role=VIEWER "--name=<Нэр Овог>" --camp-role=<КЕМП_РОЛЬ>
```
Нууц үг нэг удаа хэвлэгдэнэ → хэрэглэгчид **биечлэн / утсаар** өгнө (чат, имэйлээр биш).

| Хэн | Үндсэн `--role` | `--camp-role` | Юу хийх боломжтой |
|---|---|---|---|
| Систем хариуцагч (та) | OWNER (onboard-оор үүссэн) | Кемп админ | Бүгд |
| Кемпийн тохиргоо хариуцагч | VIEWER | `CAMP_ADMIN` | Тохиргоо, байгууллага, роль, байр/өрөө, хэлтэс, баг, ажилтан, хөрөнгө, ирц импорт, ээлж, засвар **үүсгэх** |
| Кемп менежер (захиалагч тал) | VIEWER | `CAMP_MANAGER` | Ирц импорт, ээлж зохицуулах, засвар үүсгэх, засвар **хаах/цуцлах/дахин нээх** |
| Катеринг / үйлчилгээ | VIEWER | `CATERING_ADMIN` | Ажилтан, өрөө, хөрөнгө, засвар үүсгэх, засвар **эхлүүлэх/дуусгах + сэлбэг** |

> ⚠️ Засварын урсгал хоёр рольд хуваагдсан: **эхлүүлэх/дуусгах/сэлбэг = Катеринг админ**, **хаах = Кемп менежер**. "Кемп админ" ганцаараа засвар хааж чадахгүй (OWNER/ADMIN бүгдийг чадна). Өөрчлөх хэрэгтэй бол санал болгож бүртгэнэ (PIL-09).
> Нэг хүнд хэд хэдэн роль: `pilot.ps1 user`-ийг өөр `--camp-role`-оор дахин ажиллуулна. Тодорхой нэг кемпэд л эрх өгөх бол апп-д: Кемп → **Хэрэглэгчийн роль**.
> Кемпийн рольгүй хэрэглэгч кемп рүү орох эрхгүй (403) — энэ зөв.

**Хэрэглэгч бүр:** утаснаас хаягийг нээж нэвтэрнэ → "Нүүр дэлгэцэнд нэмэх" (апп шиг ашиглана). Нийтийн компьютер дээр ажилласны дараа **Гарах** дарна.

## 2. Дадлага (1 өдөр, санал болгож байна)

Бодит өгөгдөл оруулахаас өмнө **"TEST" кодтой туршилтын кемп** үүсгэж §3–§5-ийг богино хэмжээгээр (2–3 ажилтан, 2 өрөө) хийж үзнэ. Ингэснээр бодит өгөгдөлд алдаа гаргахгүй.
- Туршилтын ажилтны код `T001`, `T002` гэх мэт (бодит кодтой давхцуулахгүй).
- Дууссаны дараа: TEST кемп → **Тохиргоо** → "Идэвхтэй"-г унтраах. Туршилтын байгууллагыг идэвхгүй болгох (ажилтнуудыг нь эхлээд идэвхгүй болгоно).
- Кемп, байгууллагыг устгах боломжгүй (идэвхгүй болгоно) — нэр/кодыг анхааралтай сонгоно.

## 3. Бодит өгөгдөл оруулах дараалал

Дарааллыг баримтална — дараагийн алхам өмнөхөөсөө хамаарна. **Код** (кемп, байр, хэлтэс, баг): зөвхөн латин үсэг, тоо, `.` `_` `-`.

| # | Хаана | Юу оруулах | Анхаарах |
|---|---|---|---|
| 1 | Кемп → **Байгууллагууд** | Уурхай (MAIN), гүйцэтгэгч, **катеринг** (үйлчилгээний төрөл: CATERING), тээвэрлэгчид | Регистрийн дугаар давтагдашгүй. Ажилтан бүр нэг байгууллагад харьяалагдана |
| 2 | Кемп → **+ Кемп нэмэх** | Код, нэр, байршил | Тохиргоо автоматаар үүснэ (НӨАТ 10%, солигдох өдөр Лхагва, 14/14) |
| 3 | Кемп → **Тохиргоо** | Хоолны байршлууд (гал тогоо, талбай г.м.) → анхдагч хоолны байршил, **катеринг байгууллага**, НӨАТ, солигдох гараг, ажлын/амралтын өдөр | Ажлын өдрийн тоог хэлтсийн ээлжийн загвар оруулсны дараа өөрчлөх боломжгүй — **эхэнд нь зөв тохируул** |
| 4 | **Байр, өрөө** | Байр (код, нэр) → өрөө (дугаар, давхар, багтаамж, төлөв) | Багтаамж 1–50 |
| 5 | **Хэлтэс, ээлж** | Хэлтэс (код, нэр, хоолны байршил) → ээлжийн загвар (өдөр 1..N: ӨДӨР/ШӨНӨ) | Загвар 1..N өдрийг цоорхойгүй бүрхэнэ |
| 6 | **Баг (ростер)** | Баг (код ≤10, нэр, **ирэх огноо**) | Ирэх огноо нь солигдох гарагт таарна (жнь Лхагва) |
| 7 | **Ажилтан** | Код (ирцийн файлын `employee_code`), нэр, албан тушаал, утас, байгууллага, хэлтэс, баг | Ажилтны код = ирцийн файлын түлхүүр — нэг стандарт мөрдөнө (табелийн дугаар г.м.) |
| 8 | **Өрөөний самбар** | Ажилтан бүрийг өрөөнд хуваарилах | 28 хоногийн багтаамжийн шалгалт — хэтэрвэл шалтгаантай алдаа гарна |
| 9 | **Ирц** | Загвар татах → бөглөх → импорт (§4) | Эхлээд одоо кемпэд байгаа хүмүүсийн **ирэлтийг** оруулна |
| 10 | Хөрөнгийн ангилал → **Хөрөнгө** | Ангилал → хөрөнгө (бараа материалын дугаар, байршил, төлөв, үнэ) | Бараа материалын дугаар давтагдашгүй |

Их хэмжээний ажилтныг гараар оруулах нь удаан бол (100+) — бүртгэх: P1 санал "ажилтан Excel-ээс импорт".

## 4. Ирц импорт (xlsx)

1. **Ирц** → **Загвар татах** → `camp-attendance-template.xlsx` ("Ирц" хуудас + "Заавар" хуудас).
2. Мөр бүр = нэг хүний нэг ирэлт эсвэл явалт:

| Багана | Заавал | Утга |
|---|---|---|
| `employee_code` | ✅ | Ажилтны код (§3-ын 7) |
| `date` | ✅ | Excel огноо эсвэл `2026-10-14` |
| `direction` | ✅ | `ARRIVAL` (ирсэн) / `DEPARTURE` (явсан) |
| `meals` | заримдаа | `BREAKFAST`, `LUNCH`, `DINNER`, `NIGHT` (таслалаар), хоол идээгүй бол `NONE`. **Багийн ростерын** ирэх/явах өдөр хоосон байж болно (ирэхэд оройн хоол, явахад өглөөний хоол). Бусад өдөр **заавал** |
| `shift` | үгүй | `DAY` / `NIGHT` — зөвхөн ирэлтийн мөрөнд (хэлтсийн загвараас өөр ээлжинд гарах үед) |

3. Файл ≤ 2 MB, ≤ 5000 мөр → **Upload** → урьдчилсан харагдац (алдаатай мөрийг шүүж харж болно) → бүх мөр зөв бол **Баталгаажуулах**. Нэг ч алдаатай мөр байвал юу ч бичигдэхгүй.

| Түгээмэл алдаа | Шалтгаан / шийдэл |
|---|---|
| Ажилтан олдсонгүй / Өөр кемпийн / идэвхгүй | Код буруу эсвэл ажилтан бүртгэгдээгүй → §3-ын 7 |
| Кемпэд байгаа хэвээр | Өмнөх ирэлтийн явалт бүртгэгдээгүй → явалтыг эхлээд оруулна |
| Кемпэд байхгүй (нээлттэй ирэлт алга) | Явалтын өмнө ирэлт бүртгэгдээгүй |
| Ээлжийн бус ирэлт/явалтад хоол заавал | Ростерын бус өдөр → `meals` бөглөнө (`NONE` болно) |
| Файлд давхардсан мөр / аль хэдийн бүртгэгдсэн | Нэг мөрийг хоёр оруулсан |
| Байх хугацаа давхцана | Огноо буруу (ирэлт/явалтын дараалал) |

Гараар: **+ Ирц бүртгэх** (нэг хүн). Буруу оруулсныг: хүний **хамгийн сүүлийн** бичлэгийг л устгана.

## 5. Туршилтын сценари

Хэн туршсан, үр дүн, асуудал гарвал FB дугаарыг бичнэ (§8-ын хүснэгт).

| TC-04 | Солигдох өдрийн явалт (xlsx) | Явсан хүмүүс тухайн шөнө өрөөний самбарт "хонохгүй" |

| TC-09 | **Хоолны тоо** (өдөр бүр, ≥5 өдөр): системийн тоо ↔ гал тогооны бодит тоо | Зөрүү бол шалтгааныг тэмдэглэнэ (ирц дутуу, ээлж буруу, "тодорхойгүй ээлж" анхааруулга г.м.) |
| TC-10 | Засвар: менежер үүсгэх (өрөө хаах) → катеринг эхлүүлэх → сэлбэг (катеринг худалдан авсан, үнэтэй) → дуусгах → менежер хаах | Дугаар `ZAS-<код>-<он>-0001`; хаахад зардлын мөр үүснэ, дараа нь засах боломжгүй; өрөө чөлөөлөгдөнө |
| TC-11 | Засвар цуцлах (шалтгаантай), дахин нээх | Төлөв зөв шилжинэ |
| TC-12 | Хөрөнгө: нэмэх → өөр өрөө рүү шилжүүлэх → актлах | Түүх, шалтгаан хадгалагдана; актласан хөрөнгөд засвар үүсгэх боломжгүй |
| TC-13 | Ажилтан идэвхгүй болгох → импортод оруулах | "Ажилтан идэвхгүй" алдаа |
| TC-14 | Олон хэрэглэгч зэрэг ажиллах (2–3 хүн нэг цагт) | Удаашрал, алдаа гарахгүй |
| TC-15 | Интернэт тасарч сэргэсний дараа хуудсыг шинэчлэх | Ажиллагаа үргэлжилнэ эсвэл нэвтрэх хуудас (давталтгүй) |

## 6. Аюулгүй байдал ба хувийн мэдээлэл (бүх хэрэглэгчид)

- Нийтийн / бусдын компьютер дээр ажилласны дараа **Гарах**.
- Ажилтны мэдээллийг (утас, өрөө) зөвхөн ажлын зорилгоор ашиглана; дэлгэцийн зургийг гадагш тараахгүй.
- Систем хариуцагч: ажилтан гарвал `pilot.ps1 user … --deactivate` тэр өдөрт нь.
